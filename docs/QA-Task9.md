## Smoke test

1. `dotnet build`.
2. `dotnet run`.
3. Открыть Dashboard.
4. Открыть карточку каждого сооружения.
5. Создать новое сооружение.
6. Создать сотрудника.
7. Распределить сотрудника в готовое сооружение.
8. Снять распределение.
9. Создать проверку.
10. Убедиться, что Condition сооружения изменился на ResultCondition.
11. Проверить фильтры сотрудников.
12. Проверить фильтр проверок.

## Негативные сценарии

- [ ] повторный RegistrationNumber → 409;
- [ ] повторный PersonnelNumber → 409;
- [ ] Capacity <= 0 → 400;
- [ ] уменьшение Capacity ниже числа распределённых сотрудников → 409;
- [ ] назначение в NotReady → 409;
- [ ] назначение сверх Capacity → 409;
- [ ] несуществующий ProtectiveStructureId → 404;
- [ ] InspectionDate в будущем → 400;
- [ ] NextInspectionDate <= InspectionDate → 400;
- [ ] удаление сооружения с сотрудниками → 409;
- [ ] удаление сооружения с историей проверок → 409;
- [ ] пробельные обязательные строки → 400.

## Демонстрационная БД

На новой пустой БД seed создаёт:

- 3 сооружения;
- общую вместимость 19;
- 8 сотрудников;
- 5 распределённых;
- 3 нераспределённых;
- по одному сооружению Ready, RequiresAttention и NotReady;
- одну просроченную следующую проверку на дату разработки.

Точные показатели Dashboard изменяются после CRUD-операций пользователя.
